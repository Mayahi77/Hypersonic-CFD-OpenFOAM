# ParaFoam export handoff

## Delivery status

The owner approved Python-generated plots after ParaFoam could not render here. The delivered images and animations are generated by `scripts/render_results.py` using Matplotlib and Pillow. They are clearly identified as Python exports, with no claim that ParaView produced them. The ParaFoam route remains available for later review.

The field renderer reads the original ASCII mesh, verifies one wedge face per cell, maps each face to its owning cell, and plots that cell's saved p or T without spatial smoothing. Its radial coordinate is sqrt(y² + z²), which projects the wedge side to the axisymmetric meridional view. Both cases use identical bounds, scales, and colormaps. GIFs contain 21 actual stored states including t = 0, advance every 80 ms (12.5 fps), and hold the final state for 800 ms. There is no temporal interpolation. The pressure/temperature line charts use the exact OpenFOAM CSVs, not gradients. A mesh comparison, sampling-location image, and saved-time-change plot are also included.

Tested analysis environment: Python 3.8.10, NumPy 1.17.4, Matplotlib 3.1.2, Pillow 7.0.0. Install the dependencies in `requirements.txt` to regenerate the figures.
Available here: OpenFOAM v1706 `paraFoam`, ParaView 5.7.0 `paraview` and `pvbatch`. No `pvpython` was found. The v1706 launcher supports `-builtin`, which selects ParaView's native OpenFOAM reader and avoids requiring a matching PVFoamReader plugin.

Attempts on disposable fine-case copies:

- `pvbatch --version` fails during Open MPI initialization because the environment cannot open network sockets. `pvbatch --no-mpi --version` succeeds and identifies 5.7.0.
- `pvbatch --no-mpi --force-offscreen-rendering probe.py` fails with `ModuleNotFoundError: No module named 'paraview'`. The installed GUI/batch package is missing the separate `python3-paraview` package. An attempted download of version `5.7.0-4ubuntu9` failed with `Temporary failure resolving 'us.archive.ubuntu.com'`.
- `paraFoam -builtin --no-mpi --force-offscreen-rendering --script=probe.py` creates a temporary case marker, then fails with `qt.qpa.xcb: could not connect to display :0` and a Qt platform initialization error.
- A Qt offscreen fallback also failed to produce an exported image; a final bounded attempt timed out without output. It did not establish a working reader/rendering pipeline.

The minimum route for manual exports is to run `paraFoam -builtin` in a session with a working graphical display. Automated exports additionally require a matching ParaView Python package, for example `python3-paraview=5.7.0-4ubuntu9` on this Ubuntu installation, and a usable rendering backend. Run outside the restricted execution environment when display/socket restrictions prevent startup. Installing the Python package alone does not fix inaccessible graphics.

## Exact requested Plot Over Line

Use reconstructed results on a disposable case copy. Both original cases already have valid reconstructed root fields; no new reconstruction is needed for these saved results.

```bash
paraFoam -case /path/to/disposable/coarse-copy -builtin
# Open the fine-copy .foam reader in the same ParaView session for comparison.
```

1. Read `internalMesh`, `p`, and `T` for both cases. Set time to **0.01 s**.
2. Use the same cell-to-point treatment for both inputs. If necessary, apply **Cell Data to Point Data** before sampling.
3. For each mesh, apply **Plot Over Line** with Point 1 **(−1, 0.375, 0)** and Point 2 **(0, 0.375, 0)**, using uniform sampling and resolution **500** (501 samples).
4. Show both lines in the same line-chart view. Select only `p` for the pressure chart, with pressure in Pa; export `results/line_pressure.png`. Select only `T` for the temperature chart, with temperature in K; export `results/line_temperature.png`.
5. Use axial x from −1 to 0 m, or clearly label arc length from 0 to 1 m as distance from Point 1. Label the coarse and fine series and t = 0.01 s.
6. Inspect valid-point indicators. Point 2 is on the front annular wall; do not interpret an invalid sample as zero pressure/temperature. Save CSVs separately as `line_paraview.csv`, since ParaView interpolation may differ from the committed OpenFOAM `cellPoint` extracts.

The CSVs already in `results/coarse/line.csv` and `results/fine/line.csv` were extracted by OpenFOAM and contain the specified 501 coordinates, pressure, and temperature. They are not claimed to be ParaView exports. No pressure-gradient plot is needed.

## Matched field views and animations

Use a z = 0 slice of `internalMesh`, looking along z with x horizontal and radius vertical. View both meshes with the same camera, scale, and crop: approximately x = −0.8 to 2 m and r = 0 to 1.4 m. The solid annular cross-section occupies x = 0–1 m, r = 0.25–0.5 m; the bore must remain visible.

Use fixed color ranges in both cases and throughout each animation:

| Field | Range | ParaView preset |
|---|---|---|
| Pressure | 0–40,000 Pa | Viridis |
| Temperature | 200–3,000 K | Inferno |

The temperature range includes startup peaks in both datasets. Turn off automatic rescaling. Keep readable legends and time annotations. Export pressure and temperature stills at 0.01 s as `results/{coarse,fine}/{pressure,temperature}.png`.

Use all available saved times for each temperature animation, without temporal interpolation. Export PNG frames into `results/{coarse,fine}/frames/`; then package them at 12.5 fps, with a short hold on the final frame. Use a matched surface-with-edges view to export `mesh.png` for each mesh and assemble `results/mesh_comparison.png`.

## Optional automatic ParaView exports after fixing the environment

`scripts/paraview_visuals.py` uses the ParaView rendering engine, its native OpenFOAM reader, and Plot Over Line. It does not make Matplotlib plots. The script has passed Python syntax checking but could not be executed here because of the blockers above; its ParaView 5.7 property compatibility and resulting visuals still need checking.

Point the variables below at **disposable copies** of the reconstructed result cases; the script creates reader-marker files inside them. It writes field stills, PNG animation frames, mesh stills, ParaView line CSVs, and overlaid p/T charts.

```bash
export PORTFOLIO_COARSE=/path/to/disposable/coarse-copy
export PORTFOLIO_FINE=/path/to/disposable/fine-copy
export PORTFOLIO_OUTPUT="$PWD/results"
paraFoam -case "$PORTFOLIO_COARSE" -builtin --no-mpi \
  --script="$PWD/scripts/paraview_visuals.py"
# Or, with the matching Python package and working rendering backend:
pvbatch --no-mpi scripts/paraview_visuals.py
# After reviewing the actual exported images:
python3 scripts/pack_media.py
```

The packaging script uses Pillow only to combine existing ParaView images and encode GIFs. It refuses to create an animation without at least two real exported frames. Raw frames are ignored by Git. After generation, check frame count, playback, labels, matched scales, and file sizes before embedding the selected media in the README.
